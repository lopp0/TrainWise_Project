## What shipped

### #185 What-if forecast simulator (ML + analytics screen)
- `ml/forecast.py` → `simulate_whatif()`; `ml/app.py` → `GET /api/ml/trainee/<id>/whatif?addSessions=&intensity=`.
- `src/services/mlApi.js` → `getTraineeWhatIf()`.

  sessions slider → live Now→simulated AC ratio + risk pills). Serves coach and trainee (#174 `self`).

### #133 Assigned training programs (full stack)
- **SQL:** `sql/2026-07-21_add_programs.sql` (run on BOTH local SQL Express and Azure SQL).
- **C#:** `Models/ProgramModels.cs`, `DAL/ProgramDAL.cs`, `BL/ProgramBL.cs`, `Controllers/ProgramsController.cs`.
- **Client:** `src/services/api.js` (program CRUD + program-chat helpers); `EventChatScreen.js` made
  channel-aware (`kind: 'event'|'program'`); new screens `ProgramBuilderScreen`, `CoachProgramsScreen`,

  (`PlannedWorkouts`, tagged `SourceAssignmentId`) + a per-program chat thread. Entry points:
  CoachTraineeDetail "Assign a program"; TrainingCalendar "My training programs".

### #121 Live GPS run tracking (frontend-only)

- `WorkoutRouteScreen.js` accepts a `routePoints` param + reads AsyncStorage (`@trainwise_route_<startISO>`)

## Deploy steps
1. **DB (both local + Azure SQL):** run `sql/2026-07-21_add_programs.sql` in SSMS. (Idempotent.)
2. **C# backend:** VS 2022 → Publish (Azure mode) AND/OR run locally — the new `ProgramsController` ships.
3. **Python ML service:** restart it (`python app.py` locally, or redeploy `ml_deploy_clean` to Azure) so
   `/whatif` is served. The what-if card and (trainee) Load Trend need the ML service reachable.
4. **APK:** JS-only across all three, EXCEPT nothing native was added — so a Metro reload shows it in dev;
   rebuild the release APK (`gradlew assembleRelease`) to ship. (expo-location/expo-maps/slider/async-storage
   were all already installed — no prebuild, no manifest change.)

## Known limitations (deliberate scope)
- #121 route polyline is stored **on-device only** (AsyncStorage), so it is not synced across devices or
  visible to the coach. Server-side route storage would be an additive `WorkoutRoutes` table later.
- #133 program edits after assignment do not retro-update already-assigned calendars (fan-out is at
  assign time). Unassign → re-assign to apply changes.
- #121 historical route redraw depends on the backend returning the workout's `startTime` in the same
  string form used as the AsyncStorage key; the immediate post-save view (direct `routePoints`) is unaffected.
